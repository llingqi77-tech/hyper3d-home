# 一整个家 · 单一场景全屋漫游

当前首页基于 2026-10-22 的 `src/main.js`、`src/layout.js` 和共享墙体版本。2026-10-23 已接入独立厨房场景，将公卫 2 门改到厨房侧，并调整主卧、儿童房、三门交汇区、客厅和客房轮廓。三门交汇区与儿童房之间的墙按确认的 L 形走线，儿童房门位于靠公卫 1 的竖墙段。十区在同一场景中，从餐厅均可连续到达。下文“户型与来源”“保真处理”记录的是未启用的 `canonical-*` 实验版，不代表当前首页；现行尺寸和位置以 `src/layout.js` 为准。

启动仓库根目录的 `启动全屋3D.cmd`，访问 <http://127.0.0.1:8765/index.html>。根目录首页和 `全屋漫游/dist/index.html` 使用同一应用；一个 WebGL 画布同时显示十个原尺寸空间，不使用 iframe 或房间网页跳转。

## 操作

1. **全屋立体**：拖动旋转、滚轮缩放；「完整墙体」可切换剖面与原墙体。
2. **正上方俯瞰**：正交相机查看完整平面布局，可拖动与缩放。
3. **房间内查看**：WASD / 方向键或触屏箭头从餐厅连续走到全部十个区域，鼠标拖动转头。空间清单仍可快速定位。
4. **逐室浏览**：依次聚焦十个房间；再次点击暂停。房间均在同一场景内。
5. **空间清单 / 房间名 / 小地图**：点击定位并查看对应的原物件。

## 户型与来源

主依据为 `references/floorplans/户型图-门位确认-2026-10-15.png`，南在图上方。所有尺寸单位为米；X 向图右、Z 向图下，Y 向上。`src/canonical-layout.js` 声明十个房间的原生尺寸、整体位置、旋转和新增连接走廊。遇到尺寸冲突时按用户确认以独立页面为准，不缩放房间或移动房内家具。

布局保留主卧/儿童房在上部，左侧餐客厅，右侧两间公卫、客房与厨房，中间公共通道。主卧阳台没有完整标注在原户型图上，按独立页面的 3.10×1.65 米尺寸放在主卧外侧。空间连接是展示估算，不能用于施工。

复用的陈设包括餐厅原 GLB 和原款桌布/摆件、用户确认的 `餐厅交互/living.js` 旧版客厅（碎花沙发、电视、绿色书桌，无独立餐桌角）、厨房最新独立灶具与柜体、公卫 1/2 资产、客房原版定制柜/书桌/床与 11 个小件、儿童房模型、主卧最新衣柜与床头柜贴合、阳台八件模型，以及交汇区四件模型。模型路径直接指向仓库已有文件；不重新调用生成服务，也不上传到外部平台。

### 保真处理

- 每间房使用独立页面的构建逻辑和模型文件；整体仅做平移、90° 倍数旋转，比例为 1，内部网格、墙地材质、纹理和家具位置不变。
- 厨房独立页原先每次随机生成台面石纹，已固定随机序列；纹理颜色与密度不变，两种页面现在可逐像素核对。
- 餐厅原页自带的旧版客厅经用户确认作为全屋客厅；同一套旧版模型在全屋只显示一次。主卧原页自带的阳台环境也只显示独立阳台一次。
- 全屋总览的剖面只作用于展示材质，不改原网格；第一人称与「完整墙体」恢复原墙体。全屋模式下主卧木门与阳台推拉门打开，保持通道可用；原独立页不受影响。

## 开发与验证

依赖复用 `厨房漫游/node_modules` 中的 Three.js / Vite。依赖未安装时先在厨房项目运行 `npm ci`。

```powershell
cd 全屋漫游
npm test
npm run build
```

构建同时更新根目录 `index.html` 的静态资源地址。原有导航页保留为根目录 `各区域网页.html`。新应用的 `dist/` 纳入版本管理；大型模型仍使用各项目原路径，需从仓库根目录启动 HTTP 服务，不能只复制本项目 dist 到另一处或用 file 协议打开。

`npm test` 检查十个原尺寸房间的平面轮廓不重叠且走廊布局相连。浏览器逐室清单在 `audit/`；`npm run test:parity` 对比原页面与打包后的全屋场景，其中旧版客厅按原餐厅页面的客厅部分核对。运行时从餐厅到十个区域的连续通行结果在 `audit/runtime-navigation.json`。
